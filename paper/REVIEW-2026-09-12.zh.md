## 本轮发现的具体问题

### 1. GLM 首轮成本结论与入库用量不一致

[首轮报告](../benchmark/results/validation-report-2026-09-11-glm-5.3-flash-s1-s22.md)称 with-skill token 约 2.2 倍、每题耗时大致翻倍。按 [usage-summary.json](../benchmark/results/artifacts/2026-09-11-glm-5.3-flash-s1-s22/usage-summary.json) 中 `skill:` 和 `noskill:` 前缀各 22 条 solver 记录汇总、排除 `judge:`：

| 指标 | no-skill | skill | skill/no-skill |
|---|---:|---:|---:|
| fresh input | 599,882 | 678,101 | 1.1304 |
| output | 116,506 | 132,726 | 1.1392 |
| total，包含 cache-read | 6,606,564 | 5,828,811 | 0.8823 |
| 累计单会话时长，秒 | 2,246.209 | 2,525.929 | 1.1245 |

因此至少需要修正或解释 headline 的统计口径。累计会话时长不是并行批次墙钟；总 token 不是美元成本。这里核对的是提交的计量产物，尚未审计原始 session 日志。

### 2. Qwen 的总体差值需要统一分母，超时不等于零分

报告的 -3.34 pp 来自 `69.89/168 − 75.05/167`，并不是完整相同分母的 task-level 配对差。由 [per_task JSON](../benchmark/results/validation-report-2026-09-11-codex-qwen3.8-27b-medium-paired.json) 按每题现有有效重复均值计算，56 题等权差为 **-3.0714 pp**；7 题改善、18 题退化、31 题持平。H8 少一个 no-skill 分数，这仍是不完整配对，需要显式披露。

若只把这一个缺失分数在合法区间 [0,1] 内做敏感性界限，统一 168 分母后的差为 **[-3.6667, -3.0714] pp**。这是缺失值敏感性范围，不是统计置信区间，也不解决旧 grader 的效度问题。

另有 **18 个 with-skill 和 12 个 no-skill trial 同时记录 timeout 与满分**。因此“超时主导失败”的论证应拆成：到预算截止时产物是否正确、会话是否正常终止、是否在无效继续探索。不能把 timeout 数当作功能失败数，也不能从总体相关性断言读取 skill 导致每一次失败。

本地模型没有 API 账单，不等于计算成本为零；保留 GPU 占用时间，费用未知则记未知。

### 3. GLM 增益集中，且部分文字解释与表格冲突

三轮逐题中位数净增 204 分，其中 S4 为 62 分，约占 **30.4%**。这不证明 S4 有问题，但应对该题独立盲评，并报告 leave-one-task/family-out 敏感性。按展示的整数表移除 S4 后，剩余 21 题仍约 +6.76 pp，不能把全部收益简单归为单题驱动。

报告称 S17“稳定正向”，但第三轮是 20→0；称 S18 稳定正向，但第一轮是 60→20。应区分“中位数正向”与“每轮均正向”。文中称 S17 的评分与 rubric 冲突，也不能直接当一般运行方差略过，应核查原答案和裁判决定。

确定性关键词裁判免于 LLM 随机性，不代表免于测量偏差。不同裁判覆盖下的成绩需要重新对齐。

### 4. 当前任务说明与 skill 条件有潜在冲突

当前 [S4 instruction](../benchmark/tasks/S4-legacy-client-imports/instruction.md) 和 [H6 instruction](../benchmark/tasks/H6-remote-error-trap/instruction.md) 写明 closed-book、fixture 外没有参考资料。与此同时实验设计拟给 with-skill 条件挂载参考资料。S4 还要求完整卡号和来源。

冻结主实验前必须核对实际传入 agent 的 prompt：明确允许读取该实验条件挂载的材料，且两臂共享中性的权限说明；不要让有 skill 的模型同时收到“没有参考资料”的指令。未提供的精确卡号/错误码应与可从 fixture 推理的诊断正确性分开。若研究的是新增事实的 open-book 效益，可以保留知识指标，但不能命名为纯程序推理增益。

这项发现针对当前源码，不自动证明历史 runner 使用了同一提示。修改 agent 可见 instruction 后，旧答案通常不能仅靠重评充当新条件运行。

### 5. 工程状态、文档状态和论文状态已脱节

`scoring.md` 开头仍列 15 个默认语义任务，生成工具实际覆盖 22 个；旧论文 audit README 记录 22 份报告，当前 results 根目录已有 37 份 Markdown 报告。它们是历史记录，不该无说明地作为当前覆盖声明。

正文 Results 仍为证据状态表，主要贡献还是 proposed design，图和卡片实例为 placeholder。补齐近期结果需要更新主文、主表生成输入、实验账本和任务暴露记录，不能只把最新均分拷贝进旧稿。

## 哪些研究必须补

### P0：先解决测量，再运行正式比较

1. 选定一个有限的正式任务集合与不可变 manifest；不要求是当前最大的 63 题。标注来源、事件族、版本、交互模式、评分终点、skill 暴露和已知缺陷。
2. 统一语义/功能评分版本。用未参与调 rubric 的真实答案开展两名独立专家评分，覆盖两臂、任务类型和分数段；30–50 份可作起始工作量，最终覆盖和区间决定是否足够。
3. 加入不带卡号的正确答案、同义改写、关键词堆砌、错误但能启动的修复、多个合法解。报告正确性假阳性/假阴性与裁判重复稳定性。oracle 满分和单元测试通过只是必要检查。
4. 将功能通过、诊断质量、资料引用和流程遵守分开。S/H 静态报告质量不能混称迁移成功率；总体混合 reward 只能作为辅助量。
5. 对完整保留产物做双臂同版本重评；若 fixture、agent 提示、资料或工具改变，则重新运行。按严格兼容性决定旧实验复用范围，不机械要求全废，也不能强行拼表。

### P0：完成能回答研究问题的对照

核心四条件仍合理：A 无资料；B 通用流程；C 同源原始 cards/docs；D distilled skill。**C 对 D 是当前最缺的关键比较。** 对齐事实覆盖、工具、检索方式与可读预算，记录实际读取量。否则 D 优于 A 只能说明整个资料包有用。

优先在两个完整受控配置上完成，而不是继续增加只有单臂的模型。跨配置不用天然相同模型名字证明可比；不同 scaffold 下分别估计条件效应。

若进一步声称长度/成本机制，增加长度匹配的无关材料或事实保持的压缩条件，在预先选定子集评测即可，不必立即全池新增条件。预算实验对每个条件对称设置，例如相同模型的原预算与更高预算，记录首次有效修改、读取量、功能正确性；不能仅给 skill 组更长时间。

Qwen 负结果适合形成“固定部署预算下的收益与代价”证据。它不能未经干预直接证明弱模型不懂 skill、skill 内容有害或长上下文是唯一原因。

### P0（若保留泛化/抗误导主张）：真正完成独立检验

- 两位真实独立标注者完成现有 packet；再仲裁并冻结 family 映射。CI 在事件族相关层重采样，不能把 336 次 trial 当 336 个独立任务。
- 把知识 holdout 与研究者未见/未调优分开。新题来自旧事件衍生不自动独立；完整重跑旧题也不恢复独立性。
- 保留鲁棒性主张需要 clean/trap × skill/no-skill 四格；只移除误导线索，保持修复目标和评分一致。分析 `(D_trap−A_trap)−(D_clean−A_clean)`，并核查轨迹。
- 若预算不足，收缩为单生态 retrospective/open-book 实证研究，把泛化和机制写成限制，不把未执行设计留作结果贡献。

### P1：统计、材料和写作

先锁定主估计量，按任务求条件差、按事件族估计区间；三次均值与中位数不在同一主表混用。保存全部尝试、基础设施异常、缺失与负结果，给出明确分母。

发布脱敏后的 trial manifest、报告/补丁、裁判 packet、细项分数、环境与资料哈希、聚合脚本。Astra/Qwen 目前“贡献者机器保留原始证据”尚不足以支撑第三方端到端复核；哈希证明完整性，不能替代可获得的内容。

主文建议保留一张任务构建/暴露划分图、一张四条件效果与成本表、一张逐事件差值图，以及一个机制实验图。用具体卡片和实际失败轨迹替换占位。不要同时扩写所有潜在 RQ。

## 相关研究带来的定位变化

除了已引用的 [SWE-Skills-Bench](https://arxiv.org/abs/2603.15401v1)，本轮发现两篇需要精读并补入比较的研究：

- [SkillLens](https://microsoft.github.io/SkillLens/) 已研究 skill 生成与使用、跨模型异质性、负迁移及格式变化。因此“不同模型效果不同”不能单独成为核心新发现。
- [Signal or Noise?（2026-08-24）](https://arxiv.org/abs/2608.23067v1) 已使用四个匹配条件、长度匹配无关对照和组件消融，报告 Web 开发中的负收益及 token 代价。因此“skill 可能降分且增加成本”本身也不够。

这里依据作者项目页和论文摘要核对研究范围，并非完成全文系统综述。进一步投稿定位需要比较全文的任务、资料、干预和验证细节，不能据摘要断言某项完全未被研究。

更值得争取的区别是：**版本锁定的真实迁移契约 + 明确来源/暴露的社区事件 + 同源事实对照 + 可执行的上下文冲突干预**。单框架研究可以有价值，但须用这些证据深度说明为何结论超出某个插件包的使用报告。跨生态数据是增强外部效度的扩展；若摘要声称跨生态普适性，则它成为必需。

## 建议执行顺序与完成标准

1. 先完成成本/分母修正、权限说明核对、实验兼容性表和正式范围选择。
2. 接着完成独立 grader 校验、事件族人工标注、四条件材料与协议冻结；这些是真正需要研究者投入的工作，不能由增加自动化脚本替代。
3. 再跑两个完整配置的核心比较，以及与论文主张相对应的独立测试和机制子集；规模依据冻结范围和预演成本确定，不机械沿用旧 448 次预算。
4. 最后统一生成表格、CI、成本和失败分析，公开复核材料，依真实结果重写摘要与结论。

完成标准不是达到正增益或固定模型数量，而是：比较可归因、评分可信、独立性说明成立、误差和缺失可见、结论有实际结果支撑、第三方能获得复核材料。即使最终 D 不优于 C，也可以形成有价值的边界或负面研究。
