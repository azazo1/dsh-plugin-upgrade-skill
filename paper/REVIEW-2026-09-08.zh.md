# 模拟顶会审稿意见：Skill-guided Framework Migration

> 2026-09-08；基于仓库 `72267b6` 的 LaTeX 主稿、任务/评分实现、冻结元数据、holdout 审计及截至 09-06 的报告；不是对未公开原始轨迹的复现，也不是正式会议审稿决定。
> 执行清单：[GAP-ANALYSIS.zh.md](GAP-ANALYSIS.zh.md)。本轮只修改审稿/计划文档，不代表已补实验或修好 grader。

## 总体判断

**以当前稿件投 ACL 主会，我倾向 Reject，原因主要是测量和归因有效性，尚不是缺少几个模型。** 目前 Results 仍是占位符，部分结论却已按正向结果写定；现有实验又混有不同快照、scaffold、网络、native skills 和评分版本。工程投入有价值，但无法据此判断最终 skill 效果的大小与稳健性。

最值得保留的方向是：社区事件驱动的版本迁移、锁定真实 Host 契约、陈旧上下文与可执行证据之间的冲突。若将贡献收敛为“专属资料如何被 agent 使用，以及何时会被误用”，并完成独立测试和等信息量对照，可以形成更有辨识度的实证论文。

对 ACL，需把问题提炼为程序性知识使用、上下文冲突与泛化的可验证研究问题；对软件工程会议，则应更突出真实项目修复、行为回归和跨项目效度。这里只是定位建议，不是对具体届次征稿范围的核验。

## 优点

1. 任务来自具体版本变化与社区实践，比纯合成的 API 改名更能捕捉迁移中的诊断难点；但“每题都有已验证独立事件”的普遍性仍需 provenance 表证实。
2. 真实 Host cold boot、版本锁定 contract seam、可追踪 checkpoint、快照生成和协议验证组成了可复用的工程基础。
3. 仓库没有隐藏负面现象：已有 native-skill 污染、无网络限制失败、oracle/评分缺陷、重评边界等报告。这些透明记录有利于建立可信研究，但需反映到正文。
4. Holdout 已有知识级审计，能够区分 absent/partial/present，而不是只按任务日期粗切；这是可以继续加强的基础。

## 主要问题（按影响排序）

### R1：核心分数可能奖励“看到了答案的表达”，而非迁移能力

[S4 历史 judge](../benchmark/tasks/S4-legacy-client-imports/tests/judge.mjs) 将四个卡号作为主要得分项，语义正确但不带卡号的答案可能失分。与此同时，[M6 judge](../benchmark/tasks/M6-sleep-tool/tests/judge.mjs) 同时含诊断、静态契约、版本信息和 cold boot 分，并非正文所说只按 Host 执行信号计分。

因此正向 delta 可能部分来自引用格式和合规项，不能全部解释为修复能力提升。[语义 pilot](../benchmark/docs/report-judge-pilot.md) 是正确方向，但 [R2](../benchmark/results/validation-report-2026-09-06-s1-s4-oracle-regrade-r2.md) 只说明四份修订 oracle 在一次评分中达满分；S2/S4 rubric 改了，Luna 未重评。不能将前后成绩拼起来证明有效性。

**必要修改**：功能/诊断/引用分拆开；对两臂保留产物统一重评；独立盲评与坏答案压力测试；多种合法解能得分。对应 T11/T8。

### R2：测试反馈参与 skill 优化，独立泛化尚未成立

[09-06 报告](../benchmark/results/validation-report-2026-09-06-three-system-paired-eval.md) 记录多轮按具体任务失败修订 checklist，且把该 skill 用于同批任务报告收益。这是有用的开发轨迹，但不能同时视为未见测试证据。“RL-optimized”也缺少足以确认强化学习方法的算法描述。

卡片写于冻结点之后，只说明某些材料对冻结 skill 不可见；不自动说明任务、事件家族或评测反馈没有参与研究者的优化决策。删除一个答案路径也不能排除其他文件中的等价知识。

**必要修改**：暴露账本、按事件族分组、先冻结后测试；若没有真正未见集合，诚实定位为 retrospective case study。对应 T13/T2。

### R3：缺少等信息量对照，无法归因于 skill 的程序组织

无 skill 与完整 skill 的差分测量的是整个包的效果，包含专属事实、程序、参考材料、脚本和可能增加的推理成本。generic 流程只能排除部分通用提示作用，不能排除“给任何正确迁移资料都一样有效”。

**必要实验**：no-skill / generic / 同源 raw cards 或 docs / distilled skill；对齐事实覆盖、工具和可读预算；必要时去脚本或去 evidence-first 指令。只有相关对比支持时才写“程序结构优于资料”。对应 T1/T18/T16。

### R4：现有跨系统差值不能作为 skill 因果收益

09-06 报告将 Claude Code+GLM with-skill 的 0.73 与另一 flash baseline 相减称 +0.17；模型、scaffold 以及任务分母都需核对，因此不构成同系统配对。该报告还使用可访问模型站点和 npm 等的网络 allowlist，不能直接填入正文的统一无网络协议结果。

[benchmark README](../benchmark/README.md) 已说明早期 Luna 19-task、Terra 22-task 并非直接模型比较，Luna 的 no-injected 条件仍有 native skills。论文却写 scaffold held constant、统一无外部访问，未承接这些限制。

**必要修改**：按 model×scaffold×snapshot×grader×资料权限分层，只在相同配置内求差；历史批次标为校准/开发，必要时重跑。对应 T14/T3。

### R5：创新性表述与已有研究不符

SkillsBench 已有配对条件、确定性验证与负收益分析；SWE-Skills-Bench 已有基于执行测试的配对评估，并讨论版本不匹配导致的退化。不能把 execution-level grading 相对“其他工作只做 output matching”，或 over-trust 本身，作为已证实独有贡献。[SkillsBench 原论文](https://arxiv.org/abs/2602.12670)、[SWE-Skills-Bench 原论文](https://arxiv.org/abs/2603.15401)。

SkillsBench 官网也已发布更新版，相关工作应固定具体 paper/dataset 版本，不能混用不同版本规模。[作者发布说明](https://www.skillsbench.ai/blogs/skillsbench-1-1)。

VersiCode 和 CODEMENV 直接研究版本相关生成/迁移；将它们一概概括为“只测模型已有知识”同样过度。应核对全文中的上下文与工具设置，再比较真正不同的研究问题。[VersiCode](https://arxiv.org/abs/2406.07411)、[CODEMENV](https://arxiv.org/abs/2506.00894)。

**必要修改**：逐项替换 `custom.bib` stub，删除未经证实的 only/none；贡献聚焦社区来源、冲突上下文、资料控制和独立事件泛化的组合。对应 T12。

### R6：“模型必然不知道”与“因此是程序迁移”均不可直接推出

正文多次断言目标晚于所有模型训练数据，所以任何收益必然来自 skill；Limitations 却承认公开资料可能已被摄入。即便公开知识截止日期可查，也不是完备污染证明。通用 semver、依赖诊断等模式还可来自旧知识或 fixture 推理。

[holdout v1](../benchmark/holdouts/temporal-holdout-v1.md) 已有 10 clean、17 mixed、25 ineligible；其中后写卡片可描述更早事件，不能直接称未来事件泛化。论文需区分知识缺失于冻结语料、测试未参与调优、真正前瞻时间划分这三件事。

**必要修改**：把“证明程序迁移”改为与受控结果相称的表述，报告绝对增益及区间；移除不可观察的先验标签。对应 T2/T5/T10。

### R7：带陷阱题上的增益，不等于抗误导能力的特有效果

一个任务即便没有误导评论也可能同样受益于专属资料。只统计 trap 子集的 with/no delta，无法判断 skill 是否降低了陷阱造成的损害。

**必要实验**：相同底层任务的 clean/trap × skill/no-skill，估计交互效应。Over-trust 要用读规则、见反证、仍跟随、导致错误的轨迹证据定义，而不是把所有负 delta 都贴该标签。对应 T15/T7。

### R8：规模、统计与论文完整性

[生成元数据](generated/benchmark-metadata.tex) 是 23 题、8S/5M/10H，且交互模式为 10 static/13 hands-on；正文仍为 24、8S/5M/11H。当前目录另有 56 个 task.toml，不代表有 56 个独立正式测试事件。相关卡片和项目产生的多任务不能当独立样本扩大有效样本量。

固定三次 median 不是充分性保证，现有汇总脚本不等于已完成 bootstrap/Wilcoxon。以模型数 ≥5 作为 P0 也没有方法学依据。

**必要修改**：family 分组 CI、明确主估计量、缺失/错误处理、成本报告；主表收敛为受控完整配置；参考文献、占位图、附录、来源许可和持久原始数据全部补齐。对应 T3/T5/T12/T16。

## 最小有说服力的补实验组合

| 实验 | 要回答的问题 | 优先级 |
|---|---|---|
| 统一 grader 的双臂重评 + 独立人工校验 | 提分是否是测量偏差 | 最先 |
| 两个受控配置、四个资料条件、重复 trial | 程序组织相对同源资料是否有额外价值 | 核心 |
| 未参与调优的事件族 + 冻结 skill | 是否超出已看过任务的修订收益 | 核心 |
| Clean/trap 四格 | 是否真正缓解误导上下文损害 | 鲁棒性主张必需 |
| 成本、激活与失败轨迹 | 效果代价是什么、何时误用 | 解释性分析 |
| 外部生态与更多模型 | 结论边界能否扩大 | 核心成立后 |

真正改善审稿判断的是：去掉卡号/表述偏差后仍有增益；相同信息预算下 distilled skill 优于 raw docs；未暴露事件族和 clean/trap 对照支持所宣称机制。如果结果不支持，也可写成严谨的负面/边界研究，不能继续保留预写的正向故事。
