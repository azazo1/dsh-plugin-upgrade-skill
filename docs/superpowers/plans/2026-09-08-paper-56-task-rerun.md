# 56 题统一重跑研究执行计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 以当前 56 题为正式评测目标，两个完整配置、四个资料条件、每格一次重新运行，形成可核查的论文主结果。

**Architecture:** 主实验测量固定任务池上的资料效用；开发暴露标签随结果保留，不把全池称为独立未见测试。旧实验只作开发、校准及历史记录，不混入新主表；稳定性分析使用看正式成绩前选定的重复子集。

**Tech Stack:** 现有 Harbor 任务、版本化 JSON manifest、CSV 审计账本、Node.js 校验/汇总脚本、LaTeX 论文。

## 本轮执行记录（2026-09-08）

本地已做评分预检并准备四条件材料，但本次 main 仅更新论文与计划，保留现有 benchmark 规则。新实验使用独立分支 `experiment/main56-v2`，评分修复与四条件材料通过 PR 评审，不合并进 main；逐次日志保留本地，只提交汇总证据。旧实验按原版本保留，可作历史结果、先导实验及有依据的配对对照；不与未来新评分结果混算。只有采用的新版本通过准入、独立校验和冻结后，才开始以下新主实验。

## 已确认的设计与预算

- 目标任务池：56 题，S=17、M=14、H=25；前缀与交互类型分别统计。
- 配置：2 个完整 model × scaffold 配置；各自记录模型、provider、agent 版本、工具和资源预算。同配置内求条件差，跨配置作描述比较。
- 条件：A 无注入资料；B 通用迁移流程；C 同源原始卡片/文档；D distilled skill。C/D 对齐事实覆盖、检索权限和预算，脚本差异单列。
- 主实验：每 task × configuration × condition 一次完整 agent 运行，共 `56 × 2 × 4 = 448` 次。一次运行内允许预算内多轮修复和测试。
- 稳定性子集：正式成绩可见前，按交互类型、事件族和陷阱类型分层选定 K 题，固定名单与选择规则；两配置四条件均额外运行两次，使子集每格合计三次。新增 `16K` 次，总计 `448 + 16K`。
- K 的具体值和名单在冻结前根据试运行成本登记；未登记不得启动正式运行。不得按正式低分、负差值或显著性选择补跑。
- 子集第 1 次始终进入 56 题主表；三次均值、波动和方向一致性单列稳定性分析，不用子集三次均值替换主表的单次结果。
- 448 不包含准入校验、试运行、人工/LLM 评分、基础设施重试及可选扩展。本轮只更新计划，不启动模型运行。

- [ ] 运行全池 448 格，按冻结顺序交错条件，每格隔离目录、记忆和输出；不复用历史成绩填格。
- [ ] 对预选 K 题对称补两次，新增 16K 格，不追加“补到成功”的运行。
- [ ] 主结果报告同配置内 D−A、D−C，A/B/C/D 四组绝对分数、功能通过率、负收益比例、覆盖率及全部成本。
- [ ] 主估计量为单次 task 差分的任务等权均值；按事件族配对 bootstrap 计算 95% CI，保持组内任务和条件配对。说明区间反映事件族间抽样不确定性，不能充分刻画每题生成随机性。
- [ ] 稳定性子集单列三次均值/波动与效果方向一致性，不增加其在全池主表中的权重；事件族很少时明确区间的精度限制。

验收：主表可从新 trial 记录重建，主运行与重复分开，负结果与异常没有静默删除。
