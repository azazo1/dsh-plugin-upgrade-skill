## Detailed findings

### #1 Source patch — hit — `A1-01`

Concrete coupling points:

- `cordis.patch.yml:2-6` composes the plugin and declares `patch.yml` as a source patch.
- `patch.yml:3-6` targets the internal source path `src/session/view/SessionView.ts` and performs a text replacement of `renderSessionView` with `renderSessionViewPatched`.
- `scripts/apply-patch.mjs:5-6` requires the legacy `DSH_HARNESS_SOURCE_ROOT` environment variable, while `:8-9` reads `patch.yml` by a legacy current-working-directory-relative path and treats it as the patch surface.
- `package.json:7` exposes the helper as the `apply-patch` script.

This is a direct source-patching/private-source coupling, mapped to `A1-01`.

### #2 Internal/persistent events — hit — `A1-02`

Concrete coupling points in `src/index.ts`:

- `:15-19` emits the `session/event` topic with the event type `legacy/informational-note`.
- `:17` depends on the `ignorable: true` event field.
- `:18` depends on the ad hoc `payload.text` shape.
- `:20-22` subscribes to the same event topic and assumes a `SessionEvent`-like object with `.type`.

Corridor folding: this is mapped to the target-state `A1-02` event contract. The intermediate alpha.1 removal of the ignorable marker is not treated as the final collision; alpha.2 restores the producer/persistence contract, so the net target state retains the producer-side `ignorable` coupling represented here. The scan therefore reports the final folded state rather than mapping this hit to a transient “field removed” state.

### #3 Internal service/Remote — hit — `A1-03`

Concrete coupling points in `src/index.ts`:

- `:25-28` registers `rename-session`, resolves the internal service with `ctx.get('apiProxy')`, and calls `apiProxy.invoke('session.rename', ...)`.
- `:29-32` repeats the same `apiProxy` lookup and invokes the `llm.providers` method.

The plugin is coupled both to the service name (`apiProxy`) and to the legacy Remote/invocation method (`invoke`) and method strings. This maps to `A1-03`.

### #4 Host filesystem/directory — hit — `A1-04`

Concrete coupling points in `src/index.ts`:

- `:4` imports `homedir`, `:6` imports `join`, and `:7` imports `writeFileSync` from the host runtime.
- `:35-38` constructs the fixed path `~/.dsh/profiles/default/legacy-note.txt` and writes to it directly.

The code assumes a particular host-owned profile layout, a default profile, and direct write access rather than a plugin-scoped directory/service. This maps to `A1-04`.

### #5 Internal UI/commands/tools — hit — `A1-05`

Concrete coupling points in `src/index.ts`:

- `:9-10` imports `SessionView` from the private package path `@deepseek-ai/dsh-session-view/internal`.
- `:41-43` uses `ctx.contributes.registerCommand('legacy.openView', ...)` and constructs the internal view with `{ enhanced: true }`.

The import is a private UI implementation path, and the command contribution is coupled to that internal view constructor and its option shape. This maps to `A1-05`.

### #6 Custom channel — hit — `A1-06`

Concrete coupling points in `src/index.ts`:

- `:4` imports the raw Node HTTP server API.
- `:47-53` creates a private loopback HTTP bridge and returns the raw server.
- `:48-50` handles requests directly and returns the literal response `legacy`.
- `:51` binds to the fixed loopback port `43121`; its comment names the private `/api/legacy` endpoint.
- `:45` explicitly identifies that the bridge bypasses the Host Gateway authentication model.

This is a custom unauthenticated channel outside the Host Gateway contract, mapped to `A1-06`. The `void startLegacyBridge` at `:54` does not remove the static coupling; it only means the bridge is not invoked in this fixture.

### #7 Subprocess/output parsing — hit — `A1-07`

Concrete coupling points in `src/index.ts`:

- `:8` imports `spawn`.
- `:59` launches `dsh --profile headless` and assumes the legacy argument arrangement.
- `:61-64` treats each arbitrary stdout data chunk as a complete line, calls `JSON.parse`, expects JSONL records, and waits for a record with `type === 'final'` and a `.text` field.
- `:65-66` resolves only the captured JSON event text.

The same output-format assumption appears in `scripts/apply-patch.mjs`:

- `:3` imports `execFileSync` and `:12-14` invokes headless `dsh` and captures text output.
- `:15-18` splits stdout into lines, parses every nonblank line as JSON, and again requires a `final` event with `.text`.

The helper is reachable through `package.json:7`. The coupling is to JSONL/event stdout, while the target headless command emits final text. This maps to `A1-07`.

## No-hit accounting and scan limitation

There are no no-hit categories in this fixture, so there is no category-specific ruled-out file set to report. The complete file set scanned is listed above; the README’s touchpoint table and the source declarations corroborate one positive sample for each category.

Even for a category that produced no textual hit, “no hit” would not establish “no problem”: this is a static, local scan and cannot see dynamically assembled imports or paths, transitive package behavior, runtime registration performed by dependencies, generated files, or behavior reached only under a particular host/version. A no-hit result would mean only that no coupling was found in the inspected files and forms.
