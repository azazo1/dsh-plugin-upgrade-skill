# S12: Global upgrade EBUSY and downgrade trap

## 1. Attempt 1: why `koffi.node` was busy

The failing copy was the native Windows addon:

```text
C:\...\@koromix\koffi-win32-x64\win32_x64\koffi.node
```

The process listing identifies the holder as **PID 42432**, the dsh web-host
`node.exe`. The host loaded `@koromix/koffi` at startup. Because `koffi.node`
is a native `.node` binary loaded by that process, Windows keeps the file in
use until that host process exits. The npm process (PID 23920) was the process
trying to copy it; it was not the holder. The agent session worker (PID 23768)
was also not identified as holding the file.

A browser refresh only reloads the web page/SPA. It does not stop the dsh web
host, unload its native module, or release the Windows file handle. The host
must be stopped completely.

## 2. Attempt 2: why it downgraded to rc.2

The README command was:

```text
npm install -g @deepseek-ai/dsh @deepseek-harness-tui/dsh-tui
```

`@deepseek-ai/dsh` has no version or tag in that command. npm therefore uses
the package's default `latest` dist-tag. At the time, the registry reported:

```text
latest -> 0.1.1-rc.2
alpha  -> 0.1.2-alpha.5
```

Thus npm freshly resolved the core package to `0.1.1-rc.2` and replaced the
installed alpha.5. An unpinned install does not preserve the currently
installed version and does not mean “the newest version by semver.” Dist-tags
are independent pointers; the `latest` pointer can be an older release line
than the `alpha` pointer. The command followed `latest`, not `alpha`.

## 3. Safe upgrade sequence for alpha.5 plus the TUI plugin

Run these on Windows, using the current dsh web-host PID. The PID `42432` is
the one captured in this evidence pack; PIDs can change after a restart.

First stop dsh from its own terminal/UI if available. If it cannot be stopped
that way, identify the current dsh host and terminate that specific process,
not every `node.exe` process:

```bat
tasklist /FI "IMAGENAME eq node.exe"
tasklist /FI "PID eq 42432"
taskkill /PID 42432 /T
tasklist /FI "PID eq 42432"
```

If the host remains after the graceful stop, use the same verified dsh-host
PID with the forced form:

```bat
taskkill /PID 42432 /T /F
tasklist /FI "PID eq 42432"
```

Only after the dsh host is gone, install the exact core version together with
the TUI package:

```bat
npm install -g @deepseek-ai/dsh@0.1.2-alpha.5 @deepseek-harness-tui/dsh-tui
dsh --version
```

The version check must print `0.1.2-alpha.5`. Then start dsh again using the
normal dsh launch command (for a direct CLI launch, `dsh`).

If tracking the registry's alpha channel is intentional rather than pinning
this exact build, `@deepseek-ai/dsh@alpha` is the explicit alternative. The
exact version is safer for this upgrade because it cannot move when the
`alpha` tag moves.

## 4. README guidance for plugin authors

README install instructions should:

1. Tell Windows users to stop the running dsh web host before a global core
   upgrade; refreshing the browser is not sufficient.
2. Pin the core runtime instead of combining an unpinned core install with a
   plugin install. For this release, use:

   ```bat
   npm install -g @deepseek-ai/dsh@0.1.2-alpha.5 @deepseek-harness-tui/dsh-tui
   ```

   Or install the pinned core and plugin in separate commands.
3. If a moving prerelease channel is intended, write `@alpha` explicitly and
   explain that it follows the mutable `alpha` dist-tag. Do not rely on npm's
   implicit `latest` tag.
4. Tell users to run `dsh --version` after installation so an accidental
   `latest`-tag downgrade is immediately visible.
