# S4 legacy client runtime migration touchpoints

## Scope and evidence

This is a read-only scan of `/app/fixture`. The fixture identifies itself as a Web Client plugin from the dsh `0.1.1-rc.2` era and says that it contains four touchpoints that break on `0.1.2-alpha.2` (`README.md:3`). Its maintainer-reference line names the four touchpoints and maps each to an upgrade card (`README.md:6`). The package declares the Web Client platform (`package.json:6`) and is private (`package.json:4`); no execution or dependency installation was performed.

The exact replacement APIs for cards A1-25, A1-27, and A1-30 are not documented anywhere in the inspected fixture. Those replacement targets are therefore marked **unconfirmed** below.

## Completeness and confidence

The four rows above are the four items enumerated by the fixture’s maintainer reference (`README.md:3,6`), and each has a corresponding source occurrence. No additional runtime touchpoint is asserted: `src/client/Pet.tsx` contains only `export function Pet() {}` (`Pet.tsx:1`), and the remaining `index.ts` declarations/imports do not match any of the four named breaking contracts (`index.ts:2-9`).

The card IDs are confirmed by `README.md:6`. Only the concrete registration replacement is fully determined from local source (`package.json:2`); the other three successor package/API paths require the actual 0.1.2-alpha.2 upgrade-card text or documentation, which is not present in this closed fixture.
