# Net state at alpha.2

src/events.ts contains produceExternalEvent, the expression delete (event as any).ignorable and a comment asking to keep that defense. I inspected it read-only. The shown event literal currently lacks the property, so deleting it is a no-op on this exact object; that does not make the intended marker-stripping policy correct.

The corridor is removal at alpha.1 (A1-02) followed by restoration at alpha.2 (A2-01). The target is alpha.2, whose persistence/reload/transport retains ignorable. Apply that final state: remove the marker-stripping statement and replace the misleading comment. Do not keep the defense and do not continue deleting the marker.

The third-party/informational event can be marked ignorable:true only if old readers can omit its semantics without harming reconstruction. Required events cannot be relabeled merely to make reload succeed. A retained marker is not an instruction to filter the event from loaded events: the event remains present after reload even if an old reader does not interpret it.

The live public Session.append call is a separate capability boundary. It has no supported ignorable parameter; adding a property through an any cast does not establish a supported live producer API. An ordinary plugin with only append must report the missing producer seam and verify a supported target persistence integration before promising marker retention. I have not confirmed an exact successor API or executed a migration. Proposed checks would preserve marked informational events across reload and reject unknown required events.
